# VP CX Agent OS — Data Schema

Generated by `python data/generate_synthetic_data.py`
Reset with `python data/reset_demo_db.py`

---

## Overview

The database contains **10 domain tables** and **2 transactional tables** (agent outputs).
All data is internally consistent: risk levels, health scores, adoption metrics, ticket counts,
escalations, and meeting notes all reinforce the same story for each customer.

---

## Domain Tables

### `customers`
Core customer record. All other tables reference `customer_id`.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PK | Stable customer identifier |
| name | TEXT | Company name |
| industry | TEXT | Vertical (Manufacturing, Healthcare, etc.) |
| employee_count | INTEGER | Company size |
| arr | INTEGER | Annual recurring revenue in USD |
| contract_start_date | TEXT (ISO) | Date contract was signed |
| renewal_date | TEXT (ISO) | Upcoming renewal date |
| lifecycle_stage | TEXT | `Onboarding` / `Mature` / `Expanding` / `At Risk` |
| health_score | INTEGER | 0–100. <40 critical, 40–60 at risk, >60 healthy |
| health_trend | TEXT | `Improving` / `Stable` / `Declining` |
| csm_owner | TEXT | Assigned Customer Success Manager |
| implementation_owner | TEXT | Assigned Implementation Manager |
| executive_sponsor_internal | TEXT | Linx internal exec sponsor |
| champion_name | TEXT | Primary customer champion |
| champion_title | TEXT | Champion's job title |
| champion_status | TEXT | `Active` / `Disengaged` / `Left Company` |
| technical_sponsor | TEXT | Customer technical contact |
| business_sponsor | TEXT | Customer business contact |
| adoption_score | INTEGER | 0–100 platform adoption score |
| sentiment | TEXT | `Positive` / `Neutral` / `Negative` |
| risk_level | TEXT | `Low` / `Medium` / `High` |
| primary_risk_reason | TEXT | Short human-readable risk summary |
| recommended_next_action | TEXT | Single highest-priority action |
| renewal_risk_score | REAL | 0.0–1.0 churn probability |
| onboarding_status | TEXT | `Complete` / `In Progress` / `Stalled` |
| security_review_status | TEXT | `Complete` / `In Progress` / `Blocked` / `Not Started` |
| arr_formatted | TEXT | Human-readable ARR e.g. `$480,000` |

**Consistency rules:**
- `health_score` < 40 → `risk_level = High`, `sentiment = Negative`
- `champion_status = Left Company` → `risk_level = High`
- `lifecycle_stage = Onboarding` + `risk_level = High` → `onboarding_status = Stalled`
- `risk_level = Low` → `adoption_score` 66–95, `sentiment = Positive`

| Column | Type | Description |
|--------|------|-------------|

| status | TEXT | `Open` / `In Progress` / `Resolved` |

### `implementation_milestones`
One row per milestone per implementation. Ordered by `planned_days_from_start`.

| Column | Type | Description |
|--------|------|-------------|
| id | INTEGER PK AUTOINCREMENT | |
| implementation_id | INTEGER FK | |
| customer_id | INTEGER FK | |
| milestone_name | TEXT | e.g. "SSO / Identity Provider Integration" |
| planned_days_from_start | INTEGER | Planned completion offset from contract start |
| status | TEXT | `Complete` / `In Progress` / `Not Started` |
| completed_at | TEXT (ISO datetime) | NULL if not complete |
| blocker | TEXT | NULL or description of current blocker |

**Standard milestone sequence:**
1. Kickoff & Scoping (day 7)
2. Technical Discovery (day 14)
3. Environment Provisioning (day 21)
4. SSO / Identity Provider Integration (day 35)
5. Initial Data Ingestion (day 42)
6. Pilot Group Onboarding (day 56)
7. Detection Policy Configuration (day 63)
8. Integration Testing & QA (day 77)
9. Security Review Sign-off (day 84)
10. Full Production Rollout (day 98)
11. Hypercare Period (day 128)
12. QBR #1 — 90-Day Review (day 180)

## Internal Consistency Matrix

| If... | Then... |
|-------|---------|
| `risk_level = High` | `health_score < 60`, `sentiment ∈ {Neutral, Negative}`, 2–4 P1 tickets, 2–3 escalations |
| `champion_status = Left Company` | `risk_level = High`, `engagement_level = None` in stakeholders |
| `lifecycle_stage = Onboarding` + High risk | `onboarding_status = Stalled`, `pct_complete < 40`, at least 1 impl blocker |
| `health_trend = Declining` | `dau_trend_30d < 0`, most recent meeting note negative |
| `risk_level = Low` | `adoption_score > 65`, `health_score > 65`, `sentiment = Positive`, no P1 tickets |
| `renewal_date within 30 days` | `requires_exec_involvement = 1` in renewals |
| `escalation.severity = Critical` | `executive_aware = 1`, meeting note references it |
